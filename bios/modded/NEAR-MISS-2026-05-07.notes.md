# Near-miss: 2026-05-07 (kept as project history)

A DS3P Rev 2.x modded BIOS (`70ADS3P2.rar`, ~2.75 MB, from the Win-Raid
[DS3P Rev 2.x offer thread](https://winraid.level1techs.com/t/offer-gigabyte-ga-970a-ds3p-rev2-x-bios-mod-nvme-added/32023))
was downloaded into this folder during the initial scaffold session, on
the assumption that the board was the DS3P (with S).

When the silkscreen was re-checked, the board turned out to be the D3P
**without** the S. The DS3P BIOS would have bricked it (the DXE Driver
Volume layout, microcode, and chipset configuration tables don't match
the D3P).

The wrong files (`70ADS3P2.rar` and the extracted `70ADS3P2/`) were
deleted by Drew the same day, before any flashing happened.

This note is kept as a historical record. If you're reading it later and
wondering "why is there a near-miss notes file in an empty BIOS folder,"
that's why.

## What the near-miss teaches

1. **Silkscreen reads are easy to fumble.** The difference between
   `D3P` and `DS3P` is one letter, and the on-PCB font size is small.
   A photo with good light, taken once, beats a verbal recollection.
2. **Project naming matters.** Files in `bios/modded/` should match the
   board they're for. A filename like `70ADS3P2.rar` makes the board
   identity audit trivially visible. If the filename and the board don't
   match, stop.
3. **Multi-source confirmation isn't optional for irreversible
   operations.** A flash command on the wrong file is one of the most
   classic "permanent damage from one mistake" scenarios. The cost of
   a second source check is roughly zero compared to the cost of a
   brick.
